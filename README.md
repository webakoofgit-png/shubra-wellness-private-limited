# Shri Shubhra Wellness

A single TanStack Start + React + TypeScript + Tailwind healthcare management frontend, with four role-aware demo workspaces. This project remains connected to [Lovable](https://lovable.dev/projects/2fd8338e-8b91-4cfc-be54-9bf1285d2afe).

## Run locally

Use Node.js 22.12 or newer.

```sh
npm install
npm run dev
```

Open the URL printed by Vite. Choose **Demo Role Switcher** on the welcome screen to explore all four roles, or use the common mobile login.

## Completed prototype workflows

- Splash, welcome, language selection, common mobile/OTP login and separate admin credential/MFA-ready screen.
- Four dashboards, desktop sidebar, mobile bottom navigation, accessible dialogs, loading skeletons, browser back navigation and role-specific screen guards.
- Explicit reference registration: use `/?ref=REF-HW1001` or the registration link generated by a worker. OTP verification is simulated before creating a patient.
- Returning-mobile account restoration retains the same Patient ID, assigned worker, surveys and order/payment records within the current browser's fictional data. An existing patient cannot be claimed by another worker reference.
- Consent-gated four-step surveys, saved survey history, admin review and assigned-worker visibility. Sales representatives cannot access health surveys.
- Worker/sales team add/edit/status management, patient details, admin reassignment with reason and audit history.
- Configurable incentive rate and eligibility, one incentive per verified patient, approval/rejection, simulated payout with payment reference, history and CSV export.
- Medicine/category management, local product-image upload, detail gallery, searchable catalogue, stock-aware cart, selected customer/address/payment method, simulated checkout and confirmation.
- Admin order status management, role-scoped order/payment history, reports with date/worker/state/district/status filters and real CSV downloads.
- Notifications with read state, profile editing, language and notification preferences, support requests, privacy/terms notices, demo recovery review and account-deletion requests.
- English, Marathi, Hindi and Kannada translation files with English fallback and browser-saved language preference.

## Demo boundaries

Use fictional details only. No real SMS, OTP, Aadhaar/KYC, card collection, payment gateway, shipping or production database is connected. All browser storage can be inspected or modified by its user. Client role guards demonstrate UX only.

`ssw-demo-v1` is versioned browser local storage. Session selection is in session storage. Clearing browser data removes the simulation; it does not provide permanent, cross-device or reinstall-safe accounts. Future centralized backend storage must provide those guarantees. The administrator can reset the fictional sample from Settings.

The interactive cards and reports derive values from the same sample records. Separately labeled network/worker scale examples show the brief's 12,450 / 245 / 65 / 14,800 and 150 / 120 / 110 benchmarks without implying those records are loaded.

## Architecture

- `src/routes/index.tsx`: one TanStack entry point.
- `src/components/wellness/`: shared shell, authentication, care, commerce, account modules and dashboard/report charts. Modules load on demand.
- `src/lib/wellness-service.ts`: typed models, fictional seeds, pure mock business operations and future `WellnessApi` interface.
- `src/lib/i18n.ts`, `src/locales/`: four language dictionaries.
- `src/styles.css`, `src/wellness.css`: semantic Tailwind tokens and responsive workspace styling.
- `docs/backend-contract.md`: future relational model and authorization/API plan.
- `docs/android-readiness.md`: Capacitor integration boundary and mobile packaging plan.

## Verification

```sh
npx tsc --noEmit
npm run test
npm run build
```

Browser checks use an existing Google Chrome installation:

```sh
npm run dev -- --host 127.0.0.1 --port 8080
# In another terminal:
npx playwright test
```

Tests cover reference attribution and duplicate prevention, account restoration, medical-record scope, incentive eligibility, audit history and stock-aware checkout. Browser scenarios cover admin navigation/CSV, survey retention, account restoration, sales checkout, reassignment/payout, language/mobile guards and medicine management. Screenshots and failure traces are written to ignored `artifacts/`.

Do not rewrite published Git history. No deployment or Git push is performed by local development commands.
